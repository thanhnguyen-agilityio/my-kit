# Onboarding checklist

## Day 0
- [ ] Project folder and git identity (`includeIf`, SSH key, signing) set up and checked
- [ ] SSH key added to the client's git host (Authentication & Signing)
- [ ] Notes repo created, `.me` link in the client repo
- [ ] Access: Slack, git host, PoC, docs, CI, password manager entry
- [ ] Asked lead whether project notes may live on GitHub

## Days 1–3
- [ ] Read Slack history and pinned messages → `people.md`, `glossary.md`, `decisions.md`
- [ ] Ran the repo locally from the README, noted every place I got stuck
- [ ] First MR: fix README or setup script
- [ ] Mapped stack, services, DB, CI/CD, environments, reviewers → `architecture.md`
- [ ] Read 10–20 recent MRs (code style, how the team reviews)
- [ ] Went through every main PoC flow → `poc-review.md`
- [ ] Marked which PoC flows are real and which are mocked

## End of week 1
- [ ] Wrote "My understanding of <product>" (goals, architecture, risks, open questions)
- [ ] Lead checked it, fixes made

## Ongoing
- [ ] `log.md` every day
- [ ] `kit-harvest.md` when something is reusable
- [ ] Monthly: clean harvest items and move them to `my-kit`
